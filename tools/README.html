Blainroe GOY and Eclectic, Sunday Workflow

A two-step PowerShell workflow for refreshing the leaderboards, the live web app, and the draft member newsletter every Sunday.

TL;DR (every Sunday)

Step 1Ingest the scorecards

Drop the day's CSVs (both Eclectic days if there's an alt day, plus the GoY results) into:

C:\Users\enkelly\OneDrive - Microsoft\Desktop\GoY_Ecclectic\Results\

Then from the repo root, run:

cd C:\Users\enkelly\BlainroeGOY-Eclectic
.\tools\Step1-IngestCsvs.ps1

This loads any new CSVs into js\preloaded-data.js, bumps the version, and pushes to GitHub. Wait one to two minutes for GitHub Pages to redeploy.

Step 2Export PDFs and draft the newsletter

Open the live app (https://enkelly-pac.github.io/BlainroeGOY-Eclectic/), which now has the new scores. Export the 5 PDFs and save them into:

C:\Users\enkelly\OneDrive - Microsoft\Desktop\GoY_Ecclectic\PublishResults\

(Just the root folder; the script moves them into a snapshot folder.)

Then run:

.\tools\Step2-PublishNewsletter.ps1 -EventName 'July Medal'

Use whatever event name fits the week ('July Medal', 'Captain's Prize', 'WH Scott Trophy', etc.). Quote it if it has spaces.

The script writes a draft to:

C:\Users\enkelly\OneDrive - Microsoft\AI Strategy\<EventSlug>_Newsletter_<yyyymmdd>.md

Open the draft, polish the wording, then it's ready to send.

Why two steps?

The 5 PDFs are an output of the same web app you're updating. So the order has to be:

  1. Push new CSVs to the app (Step 1).
  2. Let the app redeploy on GitHub Pages.
  3. Export PDFs from the now-updated app.
  4. Diff against last week and draft the newsletter (Step 2).

If you tried to do it all in one go, the "current" PDFs would still reflect last week's data and the deltas would be wrong. Step 2 actually warns you if any of the PDFs you exported are older than Step 1's ingest timestamp.

The 5 PDFs

Whatever filenames the export gives them, they must contain these patterns (the script does case-insensitive substring matching):

  • Captain's Eclectic Cup (Gross)
  • Captain's Eclectic Cup (Nett)
  • Golfer of the Year
  • Gross Eclectic Insights
  • Nett Eclectic Insights

Useful switches

ScriptSwitchPurpose
Step 1-NoPushSkip git commit/push (dry run).
Step 2-EventNameRequired. Quoted week label.
Step 2-ScorecardsAdded 187Override the "X scorecards added" headline figure. Otherwise Step 1's count is used.
Step 2-NoPushSkip git commit/push (dry run).

State file

Step 1 writes tools\.last-ingest.json with the count of CSVs appended and the timestamp. Step 2 reads it to (a) seed the "scorecards added" figure and (b) warn if PDFs are stale. Safe to delete; Step 2 will just fall back to auto-detect or ignore the warning.

Examples

Standard Sunday flow:

.\tools\Step1-IngestCsvs.ps1
# ... wait ~2 minutes, open the live app, export the 5 PDFs into PublishResults\ ...
.\tools\Step2-PublishNewsletter.ps1 -EventName 'July Medal'

Dry run, do not push to GitHub:

.\tools\Step1-IngestCsvs.ps1 -NoPush
.\tools\Step2-PublishNewsletter.ps1 -EventName 'July Medal' -NoPush

Lock the headline scorecard figure explicitly:

.\tools\Step2-PublishNewsletter.ps1 -EventName 'July Medal' -ScorecardsAdded 142

What the scripts do (for the curious)

  • tools\extract_leaderboards.py: parses the 5 PDFs into a single JSON snapshot. Handles per-PDF quirks: GoY uses "Surname, Firstname" for the current leader; Gross rows have one trailing total; Nett rows have three (gross, hcap, nett); Insights pages use value-before-label pairs with emoji bullets; etc.
  • tools\generate_newsletter.py: diffs two snapshots and writes a draft. Score-anchored (not just position-anchored) logic, so the headline goes to someone who jumped to the top of a table, not someone who shifted at the bottom because others passed them.
  • tools\Step1-IngestCsvs.ps1: runs node append-preload.js, pushes the updated preloaded-data.js to GitHub, records the appended count.
  • tools\Step2-PublishNewsletter.ps1: validates the 5 PDFs, stages them into After<EventName>\, extracts JSON from prior + current snapshots, runs the newsletter generator, drafts to OneDrive\AI Strategy\, and commits + pushes the snapshot to the repo.

When something goes wrong

Step 1: Scratch folder has files not in Results. append-preload.js errors out for safety. Move them into Results\ and re-run.
Step 2: Missing PDF. The script tells you which pattern didn't match. Re-export it from the live app and drop it into PublishResults\, then re-run Step 2.
Step 2: WARNING about a PDF older than Step 1. That PDF was exported from the still-stale app (you didn't wait for GitHub Pages to redeploy). Re-export it from the now-fresh live app and re-run Step 2.
Step 2: No prior snapshot found. The script needs a previous After*\ folder to diff against. On the very first run, manually create one with the prior PDFs in it.
Newsletter draft reads oddly. It is a draft. Open the .md file and the paired .deltas.json next to it to see the raw numbers behind every claim, then edit the prose.
Orphan PDFs in PublishResults\ root. The script picks the most recently modified match for each pattern, so old leftovers are ignored. Tidy them up into appropriately named After*\ folders when convenient.
